# 포트폴리오 내용 수정하기

이 폴더에서 내용과 사진을 관리합니다. 새 프로젝트나 경력을 추가할 때 `Portfolio.jsx`를 수정할 필요가 없습니다.

```text
portfolio/
├─ profile.json                 소개·연락처·이력서 링크
├─ background.json              학력·어학·자격·병역
├─ records.json                 논문·수상·활동
├─ projects/
│  └─ linky/
│     ├─ index.md                프로젝트 정보와 본문
│     └─ images/                 해당 프로젝트 사진
├─ careers/
│  └─ wego/
│     ├─ index.md                경력 정보와 상세 업무
│     └─ images/                 필요할 때 직접 추가
└─ templates/
   ├─ project.md                새 프로젝트 양식
   └─ career.md                 새 경력 양식
```

## 기존 내용 수정

- 소개·연락처는 `profile.json`에서 수정합니다. 이름·직무·소개는 홈과 포트폴리오가 함께 사용하며, 포트폴리오에서는 `intro`의 각 문자열이 한 줄입니다.
- 프로젝트는 `projects/<폴더>/index.md`, 경력은 `careers/<폴더>/index.md`를 수정합니다.
- 첫 번째 `---`와 두 번째 `---` 사이가 제목·기간 등의 정보입니다. 그 아래는 일반 Markdown 본문입니다.
- 새 창으로 열 문서 링크는 `profile.json`의 `documents`, 소셜 링크는 `profiles`에서 수정합니다. 소셜 `icon`은 `github`, `youtube`, `notion`을 지원합니다.
- 전화번호는 표시용 `phone`과 실제 연결용 `phoneHref`를 함께 수정합니다.
- 날짜는 프로젝트의 경우 `YYYY-MM`, 경력은 `YYYY-MM` 또는 `YYYY-MM-DD`입니다. 경력이 진행 중이면 `end: ""`로 둡니다.
- `id`는 공유 링크에 사용합니다. 기존 항목의 `id`를 유지하면 폴더 이름을 바꾸어도 기존 링크가 동작합니다.

## 사진 추가

1. 해당 프로젝트나 경력 폴더에 `images` 폴더를 만들고 사진을 넣습니다.
2. `index.md`의 원하는 위치에 다음과 같이 작성합니다.

```markdown
![로봇 정면](./images/front.png)
![시스템 구성도](./images/system.png)
```

사진들을 빈 줄 없이 연속해서 작성하면 하나의 갤러리로 묶입니다. 사진은 클릭하거나 키보드로 확대할 수 있습니다.
대괄호 안의 설명은 대체 텍스트와 사진 설명에 사용됩니다. 두 설명을 다르게 하려면 다음처럼 작성합니다.

```markdown
![로봇 정면 사진](./images/front.png "LiNKY 로봇 정면")
```

PNG·JPG·JPEG·WebP·SVG·GIF·AVIF를 지원합니다. HEIC 사진은 먼저 JPG·PNG 등으로 변환하세요.
사진 경로는 `index.md` 기준의 상대 경로입니다. 같은 폴더의 PDF도 `[자료](./report.pdf)`로 연결할 수 있습니다.
이미지 URL을 직접 관리할 필요 없이 Vite가 빌드 결과에 자산을 포함합니다.

## 본문 형식

일반 문단, 목록, 강조, 표와 코드 블록을 사용할 수 있습니다.
`####` 제목은 프로젝트의 상세 설명 박스 또는 경력의 업무 항목으로 표시합니다.

```markdown
프로젝트의 목적과 담당한 역할을 설명합니다.

- 수행한 작업
- 구현한 기능

#### 문제 해결

**문제:** 어떤 어려움이 있었는지 설명합니다.

**해결:** 어떻게 해결했는지 설명합니다.

`ROS2` `Python` `Docker`

[GitHub](https://github.com/example/project) [시연 영상](https://www.youtube.com/watch?v=example)

![실행 화면](./images/result.png)
```

백틱으로 감싼 기술 이름만 있는 문단은 기술 태그가 됩니다. 링크만 있는 문단은 자료 링크 묶음으로 표시합니다.
`[보안상 공개 불가]()`처럼 주소를 비운 링크는 클릭되지 않는 안내 태그가 됩니다.
경력의 `hardware: [...]` 목록은 로봇·센서 통합 경험 태그로 표시됩니다.

본문은 목적·본인 역할 → 구현 → 문제 해결 → 결과·한계 순서로 정리하면 읽기 쉽습니다.
성능 수치에는 측정 조건·데이터 범위를 함께 쓰고, 구현한 기능과 앞으로 할 작업을 구분하세요.
공동 프로젝트의 전체 기능을 본인 기여로 적거나, 실험 결과를 일반적인 성능·수익 보장으로 표현하지 않습니다.

## 새 항목 추가

1. `projects/my-project/` 또는 `careers/my-company/` 폴더를 만듭니다.
2. 해당 양식을 `index.md`라는 이름으로 복사합니다.
3. `id`를 다른 항목과 겹치지 않게 바꾸고, 정보와 본문을 작성합니다.
4. 실제 화면에 표시하려면 `draft: false`로 변경합니다. `draft: true`는 작성 중인 항목을 숨깁니다.

프로젝트는 시작 시점의 최신순, 경력은 종료 시점의 최신순으로 자동 정렬합니다. 진행 중인 경력은 먼저 표시합니다.
정보 영역은 간단한 문자열·목록을 지원하며, 중첩된 YAML 객체 문법은 지원하지 않습니다.
따옴표·콜론이 들어가는 값은 큰따옴표로 감싸고, 값 안의 큰따옴표는 `\"`로 작성하세요.

## 확인과 공개

`npm run dev`로 변경 사항을 확인합니다. 내용·사진의 추가와 수정은 개발 서버에 반영됩니다.
`npm run lint`와 `npm run build`로 코드·내용을 검사합니다. 필수 정보, 날짜, 중복 ID, 잘못된 상대 파일 경로는 파일 이름과 함께 오류로 안내합니다.
저장소의 `main`에 변경 사항을 반영해야 공개 사이트도 업데이트됩니다.
외부 입력을 받아 표시하는 구조가 아니라 작성자가 관리하는 Markdown을 렌더링합니다.
